Git tracks versions of your files.

Think of it as a timeline for your project.

## The basics you need

- A repository is your project folder with Git history.
- A commit is a saved snapshot of your work.
- A branch is a separate line of work for one task.
- A pull request is a request to merge one branch into another.
- GitHub is the website where you publish and share repositories.

## Simple example

You are writing a README for a project.

1. You edit a file.
2. You save the change.
3. You create a commit with a message like `Add project description`.
4. You work on a branch for a new feature.
5. You open a pull request to ask for review and merge.

## Three places to remember

1. Working directory — the files you are editing right now
2. Staging area — the changes you are ready to save
3. Repository history — all your commits, in order

## Git vs GitHub

Git is the tool. GitHub is the place where you store and share repositories online.

Use Git to:

- save work safely
- try ideas without breaking the main version
- review changes before sharing them

Use GitHub to:

- back up your project online
- collaborate with others
- open pull requests and discuss code

## Start your project

```bash
mkdir my-first-repo
cd my-first-repo
git init
```

This creates a Git repository. You are ready for the next step.
